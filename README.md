# RealtyVision

Веб-застосунок для оцінки ринкової вартості житлової нерухомості за фотографіями та характеристиками об'єкта. Система аналізує фото через мультимодальні AI-моделі, отримує актуальні ринкові ціни з DOM.RIA і розраховує вартість за математичною моделлю з коефіцієнтами.

---

## Можливості

### Оцінка нерухомості
- Завантаження до 10 фото квартири або будинку (JPG, PNG, WebP)
- AI-аналіз стану приміщень: оцінка від 1 до 5, список дефектів і переваг
- Автоматична оцінка площі за фото (якщо не вказана вручну)
- Актуальні ринкові ціни через DOM.RIA API з 7-денним кешем
- Розрахунок вартості за формулою з трьома коефіцієнтами (стан, поверх, рік побудови)
- Текстове пояснення розрахунку, сформоване мовною моделлю

### Акаунти та авторизація
- Реєстрація та вхід через email і пароль — без верифікації, одразу активно
- Перегляд особистої історії оцінок після входу
- Без акаунту — анонімна робота через ідентифікатор браузера

### AI-консультант з ремонту
- Кнопка «AI: Порахувати план ремонту» з'являється після оцінки
- Система аналізує виявлені дефекти і генерує план: 4–8 пунктів ремонту
- По кожному пункту: назва, пріоритет, вартість у доларах, очікуваний приріст ціни
- Показує загальний потенціал зростання вартості після ремонту (у відсотках)

### Порівняння оцінок
- В розділі «Історія» — відмітити 2 записи прапорцями
- Кнопка «Порівняти» відкриває таблицю side-by-side: площа, стан, ціна, рік, поверх
- Автоматично рахується різниця у ціні та відсотках

### Аналітика ринку
- Розділ «Аналітика»: загальна статистика по базі (кількість оцінок, середня ціна, топ міст)
- Графік динаміки базової ціни за м² по регіону, типу і кількості кімнат
- Дані накопичуються автоматично з кожної збереженої оцінки

### Розширена робота з історією
- Фільтри: тип нерухомості, ціна від/до, дата від/до, мінімальний стан
- Сортування за датою, ціною або станом
- Пагінація: 20 записів на сторінку
- Кнопка «PDF» на кожній оцінці — відкриває версію для друку/збереження

### Градація режимів (працює навіть без API)
Система сама обирає режим залежно від доступності сервісів:

| Режим | Vision | Ціни | Пояснення |
|-------|--------|------|-----------|
| `full` | Groq VLM | DOM.RIA live | Groq LLM |
| `full_with_cached_prices` | Groq VLM | Кеш (до 30 днів) | Groq LLM |
| `degraded` | Local CLIP | DOM.RIA / кеш | Шаблон |
| `offline` | Пропуск | Статичний файл | Шаблон |

## Перший запуск

### Крок 1. Переконатися, що Python встановлений

Відкрийте командний рядок (`Win + R`, введіть `cmd`) і виконайте:

```
python --version
```

Повинно з'явитися щось на кшталт `Python 3.12.0`. Якщо команда не знайдена — завантажте Python з [python.org](https://www.python.org/downloads/) і обов'язково поставте галочку **«Add Python to PATH»** під час встановлення.

### Крок 2. Завантажити проект

Якщо є Git:
```
git clone https://github.com/YOUR_USERNAME/RealtyVision.git
cd RealtyVision
```

Або просто розпакуйте ZIP-архів проекту в будь-яку папку.

### Крок 3. Отримати API-ключі

Система потребує три ключі. Всі безкоштовні:

**Groq** — основний AI-провайдер (аналіз фото + генерація тексту)
1. Перейдіть на [console.groq.com](https://console.groq.com)
2. Зареєструйтесь або увійдіть через Google-акаунт
3. Натисніть «API Keys» → «Create API Key»
4. Скопіюйте ключ — він починається з `gsk_`

**OpenRouter** — резервний провайдер, якщо Groq недоступний
1. Перейдіть на [openrouter.ai](https://openrouter.ai)
2. Зареєструйтесь, перейдіть у «Keys»
3. Натисніть «Create Key»
4. Ключ починається з `sk-or-`

**DOM.RIA** — актуальні ціни на нерухомість по Україні
1. Перейдіть на [developers.ria.com](https://developers.ria.com)
2. Зареєструйтесь і підтвердіть email
3. Ключ з'явиться у вашому профілі

Без ключів система запуститься в режимі `offline` — оцінка буде без аналізу фото і з приблизними статичними цінами.

### Крок 4. Налаштувати .env

У папці проекту є файл `.env.example`. Скопіюйте його:

```
copy .env.example .env
```

Відкрийте `.env` у Блокноті (або VS Code) і заповніть ваші ключі:

```
GROQ_API_KEY=gsk_ваш_ключ_тут
OPENROUTER_API_KEY=sk-or-ваш_ключ_тут
DOMRIA_API_KEY=ваш_ключ_тут
PORT=8000
```

Що означає кожен рядок:
- `GROQ_API_KEY` — ключ для AI-аналізу фото і генерації пояснень
- `OPENROUTER_API_KEY` — резервний AI-провайдер, якщо Groq перевантажений
- `DOMRIA_API_KEY` — доступ до бази цін на нерухомість в Україні
- `PORT` — порт, на якому запуститься сервер. 8000 — стандартний, можна залишити

### Крок 5. Запустити

Двічі клікніть файл `run.bat` або виконайте в командному рядку з папки проекту:

```
run.bat
```

Скрипт автоматично:
1. Створить ізольоване Python-середовище (`venv`) — щоб залежності не конфліктували з іншими програмами
2. Встановить усі необхідні бібліотеки з `requirements.txt`
3. Запустить веб-сервер

Після запуску у вікні з'явиться:
```
* Running on http://127.0.0.1:8000
```

Відкрийте браузер і перейдіть на `http://127.0.0.1:8000`.

При повторних запусках `run.bat` пропускає встановлення і запускає сервер одразу.

### Крок 6. Зупинити сервер

```
stop.bat
```

Або просто натисніть `Ctrl+C` у вікні, де запущений сервер.

## Чому ця архітектура, а не інша

### Чому Flask, а не Django?

Flask — мінімалістичний фреймворк без зайвого. Django потужніший, але вимагає ORM, міграцій, форм і маси конфігурації навіть для простого проекту. Для навчального застосунку Flask дає зрозуміліший код: кожен маршрут — одна функція, нічого прихованого.

### Чому SQLite, а не PostgreSQL?

SQLite — це файл на диску, не окремий сервер. Для запуску PostgreSQL потрібно встановити сервер, налаштувати користувача, базу, рядок підключення. SQLite не потребує нічого, просто існує. Для навчального проекту та одного сервера — це правильний вибір. Перехід на PostgreSQL при потребі — зміна одного рядка в `config.py`.

### Чому Vue 3, а не React?

Vue підключається одним `<script>` тегом без збірки. React вимагає Node.js, Webpack або Vite, package.json. Vue дозволяє написати повноцінний SPA прямо в HTML-файлі — зручно для навчання і розгортання.

### Чому Groq, а не OpenAI?

Groq надає безкоштовний API з дуже швидким inference (100+ токенів/секунду). OpenAI безкоштовно не дає нічого — потрібна кредитна картка. Для навчального проекту Groq — очевидний вибір.

### Чому аналіз фото через LLM, а не класична CV?

Класичний Computer Vision вимагає навченої моделі саме для нерухомості — датасетів по українських квартирах немає. Мультимодальні LLM (llama-4-scout) вже навчені бачити і аналізувати побутові сцени. Вони виявляють тріщини, оцінюють ремонт і розпізнають тип кімнати без додаткового навчання.

### Чому каскадний fallback (Groq → OpenRouter → local → neutral)?

API-сервіси мають ліміти, збої, тимчасову недоступність. Якщо при першому ж збої система падає — це поганий UX. Каскад гарантує, що оцінка завжди відбудеться, навіть якщо деякі компоненти недоступні. Режим завжди відображається у бейджі зверху.

## База даних

SQLite файл `realtyvision.db` створюється автоматично при першому запуску. Структура:

### Таблиця `users`
Зберігає зареєстрованих користувачів.

| Поле | Тип | Опис |
|------|-----|------|
| id | INTEGER | Первинний ключ |
| email | TEXT | Унікальний email |
| password_hash | TEXT | Хеш пароля (werkzeug pbkdf2) |
| name | TEXT | Ім'я користувача |
| created_at | TEXT | Дата реєстрації |

### Таблиця `evaluations`
Зберігає кожну оцінку нерухомості.

| Поле | Тип | Опис |
|------|-----|------|
| id | INTEGER | Первинний ключ |
| browser_id | TEXT | ID браузера (для анонімних) |
| user_id | INTEGER | FK на users (для авторизованих) |
| city_name, state_name | TEXT | Місто та область |
| realty_type | TEXT | apartment або house |
| rooms_count | INTEGER | Кількість кімнат |
| floor, total_floors, year_built | INTEGER | Параметри будівлі |
| final_area | REAL | Площа (м²) |
| condition_score | INTEGER | Оцінка стану 1–5 |
| final_price, price_min, price_max | REAL | Ціна та діапазон (USD) |
| coefficients_json | TEXT | JSON з трьома коефіцієнтами |
| factors_json | TEXT | JSON: дефекти і переваги |
| explanation | TEXT | Текст пояснення |
| renovation_json | TEXT | Кешований план ремонту від AI |
| mode | TEXT | Режим роботи при оцінці |

### Таблиця `evaluation_photos`
Фото кожної оцінки.

| Поле | Тип | Опис |
|------|-----|------|
| evaluation_id | INTEGER | FK на evaluations |
| filename | TEXT | Ім'я файлу в uploads/ |
| order_index | INTEGER | Порядок завантаження |

### Таблиця `price_history`
Динаміка ринкових цін — заповнюється автоматично при кожній збереженій оцінці.

| Поле | Тип | Опис |
|------|-----|------|
| state_id, city_id | INTEGER | Регіон |
| realty_type | TEXT | Тип нерухомості |
| rooms_count | INTEGER | Кількість кімнат |
| price_per_m2 | REAL | Базова ціна (USD/м²) |
| recorded_at | TEXT | Дата запису |

## API-маршрути

### Система
| Метод | Шлях | Опис |
|-------|------|------|
| GET | `/` | Головна сторінка SPA |
| GET | `/api/health` | Статус AI-провайдерів і режим роботи |
| GET | `/api/regions` | Список областей України |
| GET | `/api/cities/<state_id>` | Міста в обраній області |

### Авторизація
| Метод | Шлях | Опис |
|-------|------|------|
| POST | `/api/auth/register` | Реєстрація (email, name, password) |
| POST | `/api/auth/login` | Вхід (email, password) |
| POST | `/api/auth/logout` | Вихід |
| GET | `/api/auth/me` | Поточний користувач (або null) |

### Оцінка
| Метод | Шлях | Опис |
|-------|------|------|
| POST | `/api/evaluate` | Оцінка нерухомості (multipart: photos[] + параметри) |
| POST | `/api/save` | Збереження результату в базу |

### Історія
| Метод | Шлях | Опис |
|-------|------|------|
| GET | `/api/history` | Список оцінок з фільтрами, сортуванням, пагінацією |
| GET | `/api/history/<id>` | Деталі оцінки з фото |
| DELETE | `/api/history/<id>` | Видалення оцінки і файлів |

Параметри фільтрації для `GET /api/history`:
```
realty_type    — apartment або house
price_min      — мінімальна ціна (USD)
price_max      — максимальна ціна (USD)
date_from      — від дати (YYYY-MM-DD)
date_to        — до дати (YYYY-MM-DD)
condition_min  — мінімальний стан (1–5)
sort           — date_desc / date_asc / price_desc / price_asc / condition_desc
page           — номер сторінки (за замовчуванням 1)
per_page       — записів на сторінку (за замовчуванням 20)
```

### Додаткові функції
| Метод | Шлях | Опис |
|-------|------|------|
| GET | `/api/compare?ids=1,2` | Порівняння 2–4 оцінок |
| POST | `/api/renovations` | AI-план ремонту для оцінки |
| GET | `/api/analytics/prices` | Динаміка цін по регіону |
| GET | `/api/analytics/summary` | Загальна статистика по базі |
| GET | `/print/<id>` | Сторінка для друку/PDF |
| GET | `/uploads/<filename>` | Фото |

## Формула розрахунку

```
final_price = base_price_per_m2 × area × condition_coeff × floor_coeff × year_coeff
```

**Коефіцієнт стану:**

| Оцінка | Стан | Коефіцієнт |
|--------|------|------------|
| 1 | Потребує капітального ремонту | 0.65 |
| 2 | Незадовільний | 0.80 |
| 3 | Житловий стан | 1.00 |
| 4 | Євроремонт | 1.18 |
| 5 | Преміум | 1.40 |

**Коефіцієнт поверху** (тільки для квартир):

| Ситуація | Коефіцієнт |
|----------|------------|
| 1-й поверх | 0.93 |
| Останній поверх | 0.96 |
| 2–3-й у будинку 9+ поверхів | 1.02 |
| Всі інші | 1.00 |

**Коефіцієнт року побудови:**

| Рік | Коефіцієнт |
|-----|------------|
| До 1960 | 0.85 |
| 1960–1989 | 0.90 |
| 1990–2009 | 1.00 |
| 2010–2019 | 1.10 |
| 2020 і новіше | 1.15 |

**Діапазон ціни:** ±15% якщо площа вказана вручну, ±20% якщо оцінена за фото.

## Збереження та PDF

Після отримання оцінки натисніть «Зберегти в історію». Кнопка «PDF» з'явиться після збереження — вона відкриває версію для друку в новій вкладці. Щоб зберегти файл:
1. Натисніть «PDF»
2. У діалозі друку виберіть «Зберегти як PDF»
3. Натисніть «Зберегти»
